## ![⌨️](https://fonts.gstatic.com/s/e/notoemoji/17.0/2328_fe0f/32.png) Comandos y pasos importantes  
  
- `git clone [https://www.google.com/url?q=https://github.com/USUARIO/bloque-1-entorno.git&source=gmail&ust=1794685540233000&sa=E](https://www.google.com/url?q=https://github.com/USUARIO/bloque-1-entorno.git&source=gmail&ust=1794685540233000&sa=E) B1_Entorno` — clona un repositorio por HTTPS (en un repo público no pide usuario ni contraseña).  
- `git clone git@github.com:USUARIO/bloque-2-ubuntu-local.git B2_Ubuntu_Local` — clona por SSH, usando mi clave, para poder subir cambios sin token.  
- `git status` — dice en qué estado está el repositorio (y si la carpeta es un repositorio o no).  
- `git remote -v` — muestra a qué repositorio de GitHub apunta "origin".  
- `git add .` — prepara los cambios para el commit.  
- `git commit -m "Añadir mis datos de alumno"` — guarda los cambios en el historial local.  
- `git push` — sube los commits a GitHub.  
- `cd`, `pwd`, `ls -l` — moverme por las carpetas y comprobar dónde estoy antes de clonar.

## ![🚩](https://fonts.gstatic.com/s/e/notoemoji/17.0/1f6a9/32.png) Qué me ha fallado y cómo lo he resuelto  
  
- Al entrar en la carpeta clonada: `bash: cd: B1_Entorno: No such file or directory`. La carpeta se había creado con el nombre del repo (bloque-1-entorno). Lo vi con `ls` y entré con el nombre correcto.  
- Con la carpeta del ZIP: `fatal: not a git repository (or any of the parent directories): .git`. Es lo esperado: el ZIP trae los ficheros pero no la carpeta oculta .git, así que no hay historial ni se puede subir nada. Borré la carpeta.  
- Al volver a clonar: `fatal: destination path 'B2_Ubuntu_Local' already exists and is not an empty directory.` Ya existía una carpeta con ese nombre; la borré y volví a clonar.  
- En el primer intento de add/commit, git status mostraba ficheros de toda mi carpeta de usuario (../../../) y avisos como `warning: could not open directory 'Mis documentos/': Permission denied`. Estaba lanzando Git desde una carpeta que no era la de mi repositorio. Lo resolví volviendo a la ruta correcta (01_Practicas/B2_Ubuntu_Local).  
- Al hacer push: `fatal: The current branch main has no upstream branch.` y después `ERROR: Repository not found. fatal: Could not read from remote repository.` Con `git remote -v` vi que origin apuntaba a otro repositorio mío (Apuntes_Review.git). Borré el clon, lo volví a clonar por SSH desde mi copia de bloque-2-ubuntu-local y el push ya funcionó (main -> main).  
- Avisos `LF will be replaced by CRLF` al hacer add: no son errores, solo el cambio de fin de línea en Windows.  
  
## ![🤔](https://fonts.gstatic.com/s/e/notoemoji/17.0/1f914/32.png) Respuestas a las preguntas  
  
1. ¿Por qué no me ha pedido usuario ni contraseña al clonar por HTTPS? Porque el repositorio es público y bajarlo no requiere identificarse. La clave SSH y el token solo hacen falta para subir.  
2. ¿Qué pasa si me bajo el repositorio en ZIP? Que no es un repositorio, son solo ficheros: falta la carpeta .git, así que git status, git log o git push no funcionan y no puedo subir mi trabajo.  
3. ¿Qué diferencia hay con la Fase 0.3? En la 0.3 creé un repositorio vacío y no había botón "Code" que bajar; aquí el repositorio ya tiene contenido, así que lo bajo (clone/pull). Es la misma lógica pero al revés que subir (push).
